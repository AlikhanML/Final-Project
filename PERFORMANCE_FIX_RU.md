# Исправление замедления после HMM

Главная причина: контроллер повторно выполнял A* почти на каждом шаге.
Теперь отдельный RoutePlan хранит остаток маршрута внутри одной симуляции.
Он получает только оценку HMM. При движении вперёд по плану или ожидании
используется прежний план; при отклонении, возврате назад или изменении
перекрытия выполняется новый поиск. При новом запуске создаётся новый объект:
план не переносится между разными целями, картами и параметрами трафика.
Q-learning и фильтрация HMM продолжают работать.

У каждого сеанса интерфейса теперь своя копия графа. При обычном обновлении
она не извлекается повторно из pickle-кэша. Новая версия файла заменяет её.
Графы не разделяются между пользователями как изменяемый общий ресурс.
Сводная статистика карты кэшируется. Неизменившиеся слои Leaflet не
перерисовываются при повторном сообщении от Streamlit.

Проверка до/после без профилировщика на встроенной небольшой карте:
6.645 с → 2.431 с, примерно 2.73 раза быстрее. У контроллера два поиска A*.
Маршрут, GPS, HMM, confidence, временная шкала, трафик и итог совпали точно.
Это один замер на данном окружении, не гарантия времени на другом ПК.
Повторить сравнение: python benchmark_route_cache.py.

Сохраняющиеся затраты: обучение Q при изменении параметров, HMM по графу,
полный payload компонента, проверка байтов файла на Windows. Проверку Windows
не отменяли, чтобы не вернуть ошибку устаревшего кэша. Обучение не идёт заново
при обычном повторном отображении: результат симуляции уже кэшируется.
Живой Overpass и полная городская база пользователя здесь не тестировались.

Установка: извлечь архив полностью в новую папку, скопировать прежний
файл data/astana_city_roads.json, закрыть старое окно сервера, запустить
START_WINDOWS.bat и нажать Ctrl+F5 в браузере. Тесты: RUN_TESTS_WINDOWS.bat.
